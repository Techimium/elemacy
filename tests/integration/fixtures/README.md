# Architecture fixture manifest

`ArchitectureCatalog::create()` seeds actual WordPress/Elementor/ACF data and returns the IDs/settings below. Call `cleanup()` in `finally`. Names and option namespaces are unique per fixture, and deletion owns only the IDs it creates. `fixture-catalog.php` verifies the native data can be authored, read and removed. It does not claim all linked behavioral requirements already pass; the later phases add those regressions around these fixtures.

The [loop preview](../../../../../../openspec/specs/widgets/loop-item-preview/spec.md) scenarios remain authoritative for all four sources, including missing-item fallbacks and extension registration. The catalog's source records are reusable inputs for their later control/preview tests. Existing [Post Content](../../../../../../openspec/specs/dynamic-tags/post-tags/spec.md) behavior, including password protection, classic/block content and same-post recursion, remains authoritative alongside the [hardening delta](../../../../../../openspec/changes/harden-first-release-architecture/specs/dynamic-tags/post-tags/spec.md). Creating these fixtures does not replace those assertions or rewrite any existing specification.

`LibraryDocument` is the smaller fixture used for individual library lifecycle cases. The browser runner owns a separately journaled page/document pair through `browser-fixture.php` and uses the minimal native theme plus test-only MU plugins. Native PHP fixtures currently register ACF groups/options in the current request; HTTP scenarios that need ACF registration must load those same definitions during their request rather than pretend process memory persists across requests.

ACF Pro is required for the full catalog. ACF Free absence of repeaters is a hard fixture error, not a skipped/passing repeater test. No license state is changed. On ACF Pro 6.8.0.1, cleanup removes its unique options-page entry from `acf_options_page()->pages` because that version exposes no remove-page API; this is a test-only, version-sensitive cleanup boundary. Row reading/writing uses native ACF APIs.

Animations-module behavior and the separate Flexible Content proposal have no fixtures in this change. Existing popup transitions remain covered by the popup suites.
